The inversion

Twenty years of SaaS optimized distribution, not work. Service-as-Software changes the unit of sale.

SaaS worldService-as-Software
GUI first — API as an afterthought→ OpenAPI schema first; GUIs are generated from it (like this site)
Seat-based pricing→ Outcome-based — you pay for delivered results
Humans click through workflows→ Agents operate end-to-end; humans set policy
Sessions, forms, dashboards→ Goals → executions → audit trails
Docs, onboarding, webinars→ Capability registry — agents discover abilities via GET /capabilities
Chatbot bolted onto a dashboard→ Agent-native from day one. No retrofitting.

The API is the product

No React app. No login pages. No admin dashboard. Agents read the schema; this page is a thin static wrapper around the same endpoints.

# discover what the platform can do (machines read this)
curl localhost:8080/capabilities

# delegate an outcome — get an ExecutionID immediately
curl -X POST localhost:8080/goals \
  -H 'Content-Type: application/json' \
  -d '{"description": "Resolve all unresolved tier-1 tickets from last 24h"}'
# → 202 {"execution_id": "exec_…", "status": "planning"}

# collect the delivered outcome
curl localhost:8080/executions/exec_…   # outcome + full audit trail

Discovery over docs

Agents learn the system from GET /capabilities — every capability ships typed JSON-Schema contracts, never READMEs.

Autonomy by default

AGENTOS_APPROVAL_POLICY=never ships full autonomy. Human gates are explicit opt-in configuration — never architectural assumption.

Audit by construction

Every execution carries an append-only trace: plan, tasks, validations, deliveries. Replayable, greppable, honest.

Zero-key demo mode

Deterministic LLM stubs + fixture integrations. pip install, pytest green, offline. Real providers slot in via env config.
